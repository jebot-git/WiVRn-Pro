Candidate ordering from the available evidence
----------------------------------------------
1. RRB32 direct mapped decode through the actual first stereo consumer is the
   strongest measured private client candidate. Its captured median paired p50
   reduction versus matching staged input is 0.285--0.398 ms across both host
   devices/allocation labels. Every captured p50 and p95 improves in those RRB
   comparisons. This still includes private poison and three submissions, and
   small synthetic geometries retain tail regressions. The complete measured
   branch is research/sub15-20261009/mapped-input-consumer at
   068dd29df03e44ab0668d9607d2896650c4b91f9. Its README/receipt/figure include every
   paired difference, memory type and unchanged-source/input proof.
2. RRF direct mapped decode preserves the global row predictor and lower RRF
   wire size. It helps Arc, but versus the same-batch CPU image-copy reference
   UHD's captured median paired p50 difference is only -0.004555 ms; Arc RRF
   retains five p95 regressions across two repeated staged/direct comparisons.
   Keep it as an explicit native comparison arm, not a universal preference.
3. Direct image output for VR444 and palette expansion remain independently
   qualified shader options. They can preserve exact decoded bytes without the
   same RRF/RRB preprocessing, but this suite does not establish that they win
   the complete packet-to-consumer path on the headset.
4. Host image copy has actual host upload-plus-consumer evidence and strict
   feature/format/layout gates. The earlier preserved Adreno capture does not
   advertise that extension; it is not a portable default. A current host query
   does not qualify any headset. Timeline/synchronization2 prototypes qualify
   bounded stereo ownership and real buffer retirement, not latency savings.
5. GPU palette encoding from CPU input was slower than the matching CPU encoder
   in its whole measured prototype. Mapped/compact output variants and their
   negative results remain available. Encoding from an already-GPU-resident
   source would be a different input contract and is not measured here.

Native adapter work that remains concrete
----------------------------------------
The private Engine is an executable reference, not a drop-in live decoder.
The inherited source-overlay/client/decoder/test_decoder.cpp currently owns
per-eye jobs, private free image slots, queue serialization and frame metadata;
the scene retains published handles. The new adapter must reconcile those actual
owners with the following already-tested contracts:

- Admit a complete immutable stereo wire pair and bind its frame/source/target
  identity before constructing mapped_input::Pair. The codec does not supply
  transport frame identity. RRF/RRB require an explicit negotiated payload kind;
  their bytes cannot be interpreted as the existing VR444 compact grammar.
- Query/enable the exact storage and sampled image formats/views and required
  memory properties on the application's actual device. Preserve the queried
  image usages and SRGB sample interpretation. An unavailable required arm is
  unsupported, not an automatic fallback that contaminates the comparison.
- Acquire a private reusable slot whose previous upload and all renderer reads
  have retired. Pair validates both complete CRC/grammars, dimensions, capacities,
  every wire-to-destination alias and cross-eye destination alias before writes.
  Keep both immutable wire owners and mapped destinations alive synchronously.
- Permit partial private writes on an exceptional decoder result only while the
  pair remains unpublished. Pair.complete() stays false; no metadata/readiness
  submission follows. The next admitted pair must overwrite all output and tail
  padding. Preserve the prior complete displayed pair throughout failure.
- Translate private submit/fence/query operations to the application's serialized
  queue and real image layout tracking. The private benchmark waits on owned
  fences; it does not establish safe command-pool/query reuse across native eye
  threads. Borrowed application devices must not acquire private-device teardown
  behavior. Renderer retirement is distinct from decode completion or xrEndFrame.
- Keep publication atomic at the stereo identity boundary. The three-slot timeline
  model has one recording owner and one consumer submission per acquired pair;
  native retained handles and multiple renderer uses need their actual ownership
  accounting. Increasing buffered work is not assumed to reduce stale-frame age.
- Retain malformed-second-eye, late decoder failure, poisoned old outputs, exact
  decoded byte/color checks and a real first-consumer omission control in the
  adapter. Compare native CPU and GPU arms with the same packet/source identities,
  capture cadence and complete measured boundary. Record server/transport wire
  costs and scheduling separately; independent p50 or p95 values cannot be added.
