What source identity does and does not mean
----------------------------------------
Each complete encoded pair is joined through the preserved host source trace
to its canonical set of (pacer_id, app_frame_id) latches. All 2,094 known encoded
frames join unambiguously. They contain 2,071 source sets, with 23 repeated
encoded identities across the full acquisition. The actual warm-up prefix has
166 distinct encoded IDs but only 160 source sets. Among 1,910 otherwise eligible
warm encoded frames are 1,895 distinct source sets. In this run no additional
warm encoded frame is removed by excluding an already submitted warm-up set;
the exclusion remains an explicit checked rule with its own adversarial test.

A distinct application frame is not proof of a distinct simulation/input epoch,
new pixels, a changed scene, or optical freshness. This analysis never subtracts
host timestamps from client timestamps. Receive age retains its original client
clock definition. Application identities merely prevent the model from calling
two encodings of the same latched source set two distinct source generations.

Exact solver
------------
novelty_oracle.h is a separate opt-in offline solver. The original cardinality
implementation and its validated binary are unchanged. Source generation sets
must form contiguous ranges in increasing encoded-frame order; the Python front
end checks the ENTIRE known order before warm filtering, so a filtered-out
recurrence cannot hide. Noncontiguous recurrence fails closed. Source sets are
canonicalized by pacer identity; duplicate pacers or malformed identities reject.

The solver retains all encoded alternatives within each source group: later
receipt can trade against later readiness, so arbitrarily collapsing a group
would be unsound. For each deadline, exact skip budget and ending encoded frame,
the transition's prior-state prefix contains only strictly earlier source groups.
A monotone cursor adds previous-deadline states as their group becomes eligible;
same-deadline choices cannot feed each other. Skipping preserves the ending frame.
The existing frame-rank band remains a necessary (possibly loose) count bound.
The parent budget stays bounded at 25 million entries and 64 skipped deadlines.

Backtracking rechecks source-group order as well as frame/deadline/target order,
readiness and score. A separate Python audit checks actual canonical source sets
for duplicates and actual warm-up reuse, rather than trusting numeric ordinals.
It also retains all original target-admission and receive-age checks. Thus bogus
distinct ordinals cannot disguise identical source identities.

Validation
----------
source-novelty-validation-20261009.json records a fresh exact compiler command,
compiler/binary/source hashes, ASan/UBSan, 4,096 exhaustive small populations
against independent recursive enumeration over every skip budget, and 4,096
all-unique-group cases with exact original-cardinality score/path-tie agreement.
Deterministic cases include same-group alternatives with different readiness,
insufficient groups, late first choice, strict age boundary, group regression,
invalid groups/timestamps/IDs and bounded parent-memory exhaustion. Nine malformed
CLI cases reject. All 295 Python tests pass, including source-set canonicalization,
noncontiguous recurrence, missing joins, warm-up aliases and forged certificates.

Independent transport-team static review found no blocker in the group prefix,
necessary rank band, skip/backtracking logic or population underflow guard.
source-novelty-20261009.json seals all 6,500 count states, selected certificates,
the exact binary/build receipt, all loaded analysis sources, original reference
and original 300-file acquisition manifest. These hashes are rechecked after the
analysis. Original failed run05 evidence is unchanged. No live configuration,
native source behavior, transport route or release gate was changed.
