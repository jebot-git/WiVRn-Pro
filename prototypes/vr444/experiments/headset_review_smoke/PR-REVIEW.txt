P2: Bind parsed event bytes to the artifact hash (#2, #3, #4)
----------------------------------------------------------
validation/wivrn-codecs/research_workflow/neural_hooks.py:155-159 discards the
hash returned by its JSONL read. Artifacts are hashed at 208-216, reread for
metrics, then checked again only at 346-349. A replace/read/restore sequence can
therefore produce capture_validated and a 1 ms diagnostic while the receipt
hashes the original 10 ms event file. Root reproduced this on #2; neural_hooks.py
is byte-identical across all three PRs (SHA-256
0dd5a8628a4069261bde1aa1d6f08f636641de836234bf5a149039fde50a2140).

The repro uses HooksTest's synthetic fixture, changes submit timestamp_ns from
1010000000 to 1001000000 only while rows() reads events.jsonl, and restores the
original bytes before the final hash check. It does not replace parsed return
values. This requires concurrent replacement/restoration; ordinary append-only
writers generally fail the final checks. Correct adapters that finish writing
before import are unaffected. This is evidence consistency, not a claim of
independent hardware authenticity. Parse the initially hashed bytes, or compare
each JSONL read's own hash with the expected artifact record before parsing.

P2: Reject impossible stereo byte/cap accounting (#1)
----------------------------------------------------
validation/wivrn-codecs/research_workflow/manifest.py:168-172 only checks that
peak bytes do not exceed total bytes. Starting from test_manifest.completed(),
set application_cap_bytes=100 and max_stereo_serialized_bytes=100. The validator
accepts offered_pairs=2, serialized_bytes=240, and zero over-cap/rejected/fallback
pairs. These observations cannot all hold under CONTRACT.md's before-admission
stereo-envelope definition. Setting the peak to null also passes. Check the
total against offered count and peak, and require a disposition where the
observations necessarily imply an over-cap pair. Root reproduced both cases.

P2: Apply the native RRB32 pixel bound to decision plans (#4)
----------------------------------------------------------
validation/wivrn-codecs/neural_encoder_decisions/core.py:269 checks axes <=4096
but omits the inherited 4,194,304 pixels/eye limit. Root reproduced:
  core.plan(bytes(4096 * 1025 * 3), 4096, 1025, "fixed_up")
It accepts 4,198,400 pixels and produces a 33-block plan. The 12,595,200-byte
input also fits native.py's 16 MiB allowance, but the native RRF/RRB codec rejects
that shape. Enforce the product bound, or an explicit unsupported disposition,
before invoking the native adapter. The wrapper's exact-output checks do not
turn this unsupported input into a native pass; the issue is profile admission.
