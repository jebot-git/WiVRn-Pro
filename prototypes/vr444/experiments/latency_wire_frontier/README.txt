Frozen codec-tail and serialized-wire frontier
=============================================

This offline model asks when the fused encoder's measured host CPU savings
survive its wire size, and whether median and p95 conclusions differ. It consumes
the exact paired31-sample observation from rowblocks_fused_encoder at355b3b1.
Four arms are original VR444+optional WPC1, global RRF-up, RRB32 fused4 and RRB128
fused4. All RRB clients used four host workers. Twelve actual captured pairs and
fourteen explicitly duplicated-eye synthetic profiles remain separately labeled.
No measured GPU value or physical clock is added to these host samples.

Total encoded byte counts drive the actual bounded VXF1 packetizer and receiver.
Generated byte content and the equal left/right split are synthetic; they do not
change framing lengths. A1us-per-record logical replay establishes which complete
record passes both-eye CRC/recovery gates, without interpreting that replay as a
network measurement. Scenarios are clean and first source record erased, with
stripe widths0/4/8/16. VXF's unchanged256KiB stereo limit applies; oversized input
is ineligible without truncation or quality change. CRC/parity are not security.

A second calculation serializes each actual record length plus declared28-byte
IPv4/UDP or48-byte IPv6/UDP base headers at finite50/100/300/600/1000/2500/10000Mbps.
Each record duration rounds up to an integer nanosecond. Erased records and late
unused parity consume service and load. No propagation, link/MAC, security, ACK,
queueing, jitter, loss probability, congestion control, packet processing cost,
rendering, runtime, display or encode/send/decode overlap is modeled.

The model100ms receiver ticket begins at declared wire service start. Assembly
must precede it strictly; a separate field reports whether every measured client
decode sample also fits its remaining time. The model's wire-only90Hz capacity
condition uses all serialized bytes, including unused parity. Neither condition
establishes real endpoint throughput or production deadline behavior.

Two horizons
------------
full: measured paired server+client sample plus service start to assembly.
first_record: measured client sample plus first received record to assembly.
The latter excludes source preprocessing and service before that first record;
it does not include xrEndFrame and is not the strict native headset gate.

Since service is deterministic within each declared case, its constant shifts
the measured p50/p95/max exactly. This does not create a real latency distribution
or confidence interval. Reported group means average four fixed pair quantiles;
they are not pooled live percentiles. The host had no frequency, thermal or
affinity controls, and31 samples do not characterize rare scheduling tails.

For each captured case, candidate, quantile and horizon, the continuous ideal
candidate-minus-baseline difference is:
  CPU_delta_ms + service_bits_delta / (rate_Mbps *1000).
Its sign gives an ideal crossover or dominance class. Nearby integer-Mbps rates
are checked with exact per-record nanosecond rounding and the modeled ticket.
The ideal boundary is not a guarantee about every rounded rate or an estimate of
available connection speed. Offline content-specific crossovers are not an
implemented adaptive selector; an executable policy would need negotiated format,
bounded admission and independent quality/latency validation.

Provenance and reproduction
---------------------------
The runner verifies the frozen benchmark against its measurement receipt and
rehashes every measured source dependency. It also binds its own model, the VXF
and receiver-lifetime sources, and the benchmark validator before and after the
calculation. Existing output is refused. The row table retains a stable column
list, with null for fields absent in incomplete/ineligible cases.

  python3 -m unittest discover -s prototypes/vr444/experiments/latency_wire_frontier
  python3 prototypes/vr444/experiments/latency_wire_frontier/frontier.py /tmp/frontier.json

No sockets, headset, GPU or production configuration is accessed. Results cannot
promote a branch to sub15; headset testing remains suspended.
